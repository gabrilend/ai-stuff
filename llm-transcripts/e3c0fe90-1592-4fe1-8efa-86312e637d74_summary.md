### Assistant Response 1

I have enough to answer your question. Here's how the two systems work.


## The transcript pipeline


Claude Code stores every session as a JSONL file in
`~/.claude/projects/<encoded-project-path>/<session-uuid>.jsonl` — one message
per line, with `type: "user"` / `"assistant"`, tool calls, tool results,
timestamps, UUIDs. Both transcript tools read from there. The path-to-directory
encoding is just `/` → `-` with a leading `-`, so
`/mnt/mtwo/programming/ai-stuff/words-pdf` becomes
`-mnt-mtwo-programming-ai-stuff-words-pdf`.


## System 1 — `backup-conversations` (the simple one)


Lives at `scripts/backup-conversations`. Takes a project path, finds the
matching Claude directory, and for each `.jsonl` calls a Lua parser
(`scripts/libs/conversation-parser.lua`) that walks the message stream and
writes a markdown file containing only the **user requests and the last
assistant text response per turn** — tool results and intermediate assistant
messages are dropped. Headings get downgraded (`###` → `##`), prose is wrapped
to 80 cols, code/lists/headers are left alone, and the output file's mtime is
set to the conversation's final timestamp. Output goes to
`<project>/llm-transcripts/<uuid>_summary.md`. If `fuzzy-computing` is on PATH
it asks a local LLM to invent a 3–5 word descriptive filename and renames the
file.


That's the format you see today — your
`neocities-modernization/llm-transcripts/9ff2aa98-..._summary.md` was made this
way.


## System 2 — `claude-conversation-exporter.sh` (the heavy one)


Lives at `scripts/claude-conversation-exporter.sh` — 1973 lines. Same JSONL
source, but built for browsing and adjustable detail:


- Six verbosity levels: **v0 minimal** (just code blocks), **v1 compact** (drops sentiments), **v2 standard** (default, full conversation), **v3 verbose** (adds context files), **v4 complete** (adds LLM execution details + vimfolds), **v5 raw** (all intermediate steps and tool results).

- TUI project browser with partial-ID matching.

- Self-modifying — stores per-project output paths inside its own source between `# STORED_PROJECT_PATHS_START`/`END` markers.


## The wrapper — `batch-transcript-backup.sh`


This is what ties the two together for a many-project run. It uses
`delta-version/scripts/list-projects.sh` to discover projects with
conversations, then for each project: runs `backup-conversations` to make the
baseline `_summary.md` files, then (if `--all-verbosity-levels` or
`--verbosity-range N-M`) loops over the chosen levels and re-exports each
conversation via `claude-conversation-exporter.sh` as `<id>-v<N>-<name>.md`.
Flags: `--all`, `-I`, `-v N`, `--verbosity-range`, `--dry-run`, `--commit`.
