# Will Not Implement

Issues that were written as blueprints for something the design later stopped
wanting. They are kept, not deleted, because **the road not taken is worth being
able to find** — the same reason the open-questions page rewrites superseded
answers rather than removing them.

They are out of `issues/` proper so that the active list is honest about what is
still to be built, and so the validator stops asking the roadmap to account for
them.

**Each file keeps its body exactly as written**, with a short note added at the
top saying what replaced it and why, and its relative links repaired for the
move. Nothing else is edited, ever. If a cancelled design comes back, it comes
back as a new issue that can cite this one.

| Issue | Was going to build | Replaced by |
| --- | --- | --- |
| 406 | Locking a placement | Individual ownership made it unnecessary — nobody can move your stones. See F29 and F31. |
| 407 | Two objections open a lock | Same. The disclaim-and-reset cycle does the job a two-key rule was doing, and scales to any team size. |

The numbers are not reused. 406 and 407 are spent.
