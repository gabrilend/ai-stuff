# 304 — A gallery you can page through

## Current behavior

A run produces thousands of directories of PNGs and JSON. Nobody is going to open
thousands of directories.

## Intended behavior

**One HTML page per set, showing every character at the size the illusion is
supposed to work at.**

The specification of this whole project is *a person squints at a thumbnail and
sees the character* (`docs/003`). This is the instrument for that. It is not a
convenience.

So the design follows from the test rather than from taste:

- **The field is shown small by default**, because small is where it must work.
  Large is where it must fail. Both are one click apart, and seeing the same image
  at both sizes is the entire evaluation.
- **The character is printed beside its field**, large and in a real font, so the
  comparison is immediate and does not depend on the viewer knowing the character.
- **The arrow layer toggles over the field**, since the question *are these arrows
  legible at this size* is separate from the question *is the character legible*.
- **The prompt and the reasoning are visible per character** — the biome, which
  components became subjects, which were demoted to landscape for being phonetic,
  what object each named stroke is carrying. When an image is wrong, this is
  where the wrongness will be, and it will be visible in the reasoning before
  anybody generates anything.
- **Filterable by biome, grade, JLPT and stroke count**, because "show me every
  character that landed in the fire biome" is how you find out that the fire
  biome is catching things it should not.

**Generated by a program, not written.** A run with a different set produces a
different gallery, and a gallery that had to be maintained by hand would stop
matching the set immediately.

**Self-contained and offline.** One HTML file next to the images, opened from the
filesystem. No server, no fetched libraries. Anything else means "it works on the
machine that generated it".

## Suggested implementation steps

1. **`src/032-a-gallery-you-can-page.lua`**, reading the `card.json` files a run
   left behind. It never recomputes anything — if the gallery disagreed with the
   run, the gallery would be a second implementation of the scene grammar.

2. **Page it.** Six thousand characters at two images each is not one page. Fixed
   page size, navigation, and the filters applied before paging.

3. **The aesthetic is the project's**: paper, ink, a great deal of white space, one
   accent. It is shared with the documentation site in `305` — one stylesheet,
   written once, used by both.

4. **Test that it renders every card in the set** and that a set with a missing
   file produces a visible gap saying which file is missing, rather than a broken
   image. A silently broken image is a bug that gets attributed to the generator.
