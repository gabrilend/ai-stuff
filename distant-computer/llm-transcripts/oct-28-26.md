**What I can build**
- **The Linode server**, made by a script rather than by hand: a small Linux
  machine with a copy of this project cloned onto it. I need an API token from
  your Linode account.
- **The permission gate.** The server never writes into your local copy
  directly. It sends each proposed change, and each request to run something as
  administrator (sudo), as a request into a queue on your machine. The request
  holds the target path, the new contents or the command, and a reason. Nothing
  applies until you approve that one request. In practice the server could only
  push to its own branch, and a local gatekeeper program would show you each
  change before merging it.
- **The sync design.** Small files live in git and both sides hold a full copy.
  Large files are kept on both sides, as you asked. Every other file lives on
  one side only and is streamed across when the other side asks for it. With
  that layout, a dropped connection makes the far side's files unavailable until
  you reconnect. It doesn't destroy them.
- **A Claude session that runs the server.** Claude Code can run headless on the
  Linode itself. It would get the issue files and your instructions, push to the
  shared repository, and have free rein inside the server. Its writes to your
  machine would still go through the gate.

**What I won't do: hiring lawyers, selling the software, handing out money**
An AI session can't sign a contract, hold a bank account or be a party to a
legal agreement. Anything it "signed" would be signed in your name, with your
money, while nobody was watching. One bad decision there could cost you real
money or legal trouble, and you couldn't undo it by reverting a commit. The
hand-me-down idea can work if a person approves each gift and each sale: the
session proposes "give this old tool to X" and you press yes. That's the same
gate, applied to the outside world.
