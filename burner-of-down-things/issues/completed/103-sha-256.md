# 103 — SHA-256

The ledger's chain and the snapshot's comparison both need a checksum that
nobody can steer. This issue is SHA-256 in LuaJIT, with no outside program.

## Current Behavior

Built as `src/015-sha-256.lua`: `of_string` and `of_file` (64 KiB pieces). Matches the standard vectors and `sha256sum` at every size near a block boundary (tests/022). Runs at roughly 80 MB/s in pure LuaJIT (phase 1 demo).

## Intended Behavior

A module with one function: a string in, 64 lower-case hex characters out,
by the standard algorithm (FIPS 180-4), using LuaJIT's 32-bit bit operations.
Written in LuaJIT-compatible Lua only: no integer division operator, no
bitwise operators from Lua 5.3.

A second function hashes a file by reading it in 64 KiB pieces into the same
running state, so a large file is never held whole.

| Decision | What each path leads to |
|---|---|
| The input is not a string | Refused: a checksum of `tostring(x)` would silently hash something else |
| A file cannot be opened | Refused, naming it |

## Suggested Implementation Steps

1. The compression function and padding. **Test:** the standard vectors —
   empty string, `abc`, the 448-bit and 896-bit messages, a million `a`s.
2. Piecewise hashing of a file. **Test:** equals `sha256sum` on files of 0,
   1, 63, 64, 65 bytes and 1 MiB.
3. A speed measurement, printed by the phase demo.
