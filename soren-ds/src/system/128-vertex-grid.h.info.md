# 128-vertex-grid.h

`src/system/128-vertex-grid.h` — generated by `scripts/generate-info` from the file's own comments; edit those, not this.

the modeller's grid of placed vertices (issue 1001).

General description: the modeller's canvas is a cube of 32 x 32 x 32
cells. A cell is empty or holds one vertex. A grid is the set of
vertices placed so far, looked up by their cell: a hash table keyed by
the cell's three coordinates packed into 15 bits, over a dense array
of the vertices themselves, so that walking every vertex costs what
there is and not what there could be.

A vertex is its cell plus the head of its list of faces. Faces arrive
in 1003; until then every list is empty (head -1, count 0), and the
grid only keeps the fields where 1003 will hang them.

A grid's memory belongs to its app, through 127 — which is the
STAND-IN for 902's per-app region: the grid asks for its app's memory
the way it will once 902 exists, but until then the memory comes from
the engine's shared allocator, and only the app's budget is enforced.
A grid that cannot grow refuses the placement and is left as it was.

Grids are named by small numbers. Every call is safe from any core: a
grid has its own lock, held only for one lookup, placement or removal.
Answers are copies, never pointers into the grid, because another core
may grow or reorder the grid the moment the lock is let go.

## What it declares

### vertex_grid_alloc

```c
int vertex_grid_alloc(int app)
```

A new, empty grid whose memory is `app`'s. Answers its number, or
VERTEX_NO_GRID when every grid is in use, or VERTEX_NO_MEMORY.

### vertex_grid_free

```c
int vertex_grid_free(int grid)
```

Give it and all its memory back.

### vertex_grid_place

```c
int vertex_grid_place(int grid, int x, int y, int z)
```

Place a vertex in a cell: VERTEX_PLACED, VERTEX_UNCHANGED if one was
there, or a negative answer.

### vertex_grid_remove

```c
int vertex_grid_remove(int grid, int x, int y, int z)
```

Take the vertex out of a cell: VERTEX_PLACED, VERTEX_UNCHANGED if the
cell was empty, or a negative answer.

### vertex_grid_at

```c
int vertex_grid_at(int grid, int x, int y, int z, struct vertex *out)
```

The vertex in a cell: 1 and a copy in `out`, 0 if empty, or a negative
answer. `out` may be NULL.

### vertex_grid_count

```c
int vertex_grid_count(int grid)
```

How many vertices, and copies of them from the `start`th, up to `max`;
answers how many were copied. The order is the grid's own: placement
order, except that a removal moves the last vertex into the gap. A
walk that wants an order of its own sorts.

### vertex_grid_list

```c
int vertex_grid_list(int grid, int start, struct vertex *out, int max)
```

### vertex_grid_app

```c
int vertex_grid_app(int grid)
```

The app a grid's memory belongs to, and how many bytes it holds.

```c
size_t vertex_grid_bytes(int grid)
```
