**What it does, in order:** opens a single ssh connection to the dev machine and

**Decisions worth knowing about:**

- **The dev machine is a required argument, not a hard-coded value.** The USB
  drive's UUID belongs to hardware you own; the network route between two
  machines is a property of whatever network they're sitting on that day, and a
  stale hostname in a script that builds and flashes is worse than no hostname.
- **Only `bootable-sd.img` crosses the wire.** Your `output/` also holds a 2.2
  GB ROCKNIX reference image. The USB route could afford `rsync --delete` over
  the whole directory; a network copy of it would be absurd.
- **The image stages in RAM and costs almost nothing.** Measured on the real 285

  of actual RAM**, not 272. Compression does the same job on the wire.
- **Hashing at both ends is new.** A drive's failure modes are visible — you
  know if you pulled it early. A network transfer into a tmpfs has quieter ones,
  and the check costs about a second.
- **No sudo of its own.** The one privileged step is the raw device write, which
  belongs to `flash-sd`.

**4 — recreating `tmp/` before use.** Your instinct was right, but plain
`mkdir -p` can't do it, and I'd have shipped a broken fix if I hadn't checked.
`tmp/` is a *symlink* to `/tmp/soren-ds`. When the target is gone, `mkdir -p
project/tmp` fails with `File exists` — mkdir sees the symlink, stops there,
and never looks at where it points. The path has to be resolved first:

```
mkdir -p "$(readlink -f "$TMP_DIR")"
```

Fixed in the Makefile (resolved once at parse time, with an error if it resolves
