## What the design changed to

            **A station line's box address always names a file.** `station adder
(boxes/math.c:add)`. A bare function name is refused at read time with the shape
that replaces it. Two of the three old forms resolved by *searching* — and the
  search had two implementations that disagreed, one matching a name as a suffix
of a box's path, one joining it to the description's directory, so a description
        could build under one reader and be refused by the other. Both are gone.

**A file name in a description means exactly one path.** Apply the description's
         shortcuts to the first segment of the address, join what is left to the
   directory the description itself lives in unless it starts with `/`, collapse
 doubled slashes. Nothing is searched. One function does it and both callers —
  the compiler finding sources to parse, the emitter deciding which parsed box a
                                           line means — ask that one function.

         **A shortcut block sits before the stations.** `boxes = ../src/boxes/`,
    recognised by the second word being `=`, which no station line can have. The
 blueprint had two kinds of shortcut, a directory one and a file one, told apart
       by a trailing slash. **That distinction lasted about an hour and does not
  exist**: a shortcut is a piece of path standing in for the first segment of an
address, and `libs` and `libs/` are the same piece of path the way they are to a
 shell. The docs and issue 610 both still carried the two-kind table; they don't
                                                                            now.

 **`serac` lost the C files from its command line.** `serac accumulate.map` is a
 program. The description already names every file, so a second statement of the
     same fact was a place the two could disagree. The one form that still takes
   sources that way is `--shared boxes.c`, which has no description to read them
                                                                           from.

  **A dump is a program.** It writes `grown.map` plus `grown.functions/` holding
   the source of every box a station actually places — deduplicated, basenames
       kept, a number before the extension where two collide. Every station line
  addresses its box inside that directory. A box built into the binary and a box
 compiled while the program ran come out identical, which retired the dump's old
          habit of shortening a late box's address back to a bare function name.

**And the load path collapsed rather than being fixed.** Reading a map file used
  to copy the file into a scratch directory, spill the running program's own box
 sources beside it, and compile the copy. A map that names its own sources needs
   no spilling, so a map file is now compiled where it sits, whole — **nothing
       binds, so nothing can fail to bind.** Only map *text* handed to a running
             program still goes to scratch and binds to what the host published.

## What changed, and why each one was worth taking

      **The map file format is now the parent's, unnarrowed.** The fork's stated
 premise — that soramech's format was a directory of files, one per box, built
  for a machine with a filesystem and a text editor — was never true; it's one
         line-oriented text file as well. Five things came with the convergence:

   - **The kind is the first word** (`station`, `comparator`, `iterator`), not a
       third column. Every line announcing itself is what lets the format gain a
        keyword later without stealing a name from a map somebody already wrote.
- **A box address names its file** — `boxes/text.c:say`, never `say`. This one
     matters more on soren-ds than on a workstation, and that's the argument I'd
    put in front of you: a box compiled at the touchscreen has to say which file
    it came from, or a program's description says nothing about what the program
                                           is made of and **cannot be rebuilt**.
  - **Paths are relative to the file they're written in, and nothing is searched
             for.** soramech had two resolvers that disagreed; the symptom was a
         description one reader accepted and the other refused, naming a file it
                                                                  couldn't find.
- **Every wire is written at both ends**, so reading one station tells the whole
  truth about it. Four kinds of disagreement between the two ends are told apart
                                                    and all reported in one run.
 - **A door is a `$` on a port, not a designated station.** This is the one that
                                                      shows up in a measurement.

**An argument stopped costing a station.** soren-ds's design paid, per argument,
a station record, a mutex, a ring buffer, and then *per value* a task allocated,
  a dispatch through the pool, a call that returns its own argument, a readiness
   check and a second delivery — to move a value one hop. With the mark on the
 port, the outside's value lands directly in the port of the station that wanted
it. Four cores and 3 GB is exactly the machine where that's worth not paying. It
also answered one of soren-ds's own open questions for free: *can a program have
        more than one door out?* Yes — several marked output ports are several
 numbered results, and a caller asks by number. It only looked hard while a door
was a station, because then two doors out meant two stations each claiming to be
                                                                        the end.

    **A station can be removed.** The restriction was stated in five places. The
 overturn is one observation: a wire exists only as a destination record on some
   station's output port, so cutting every wire that names a station is a single
        walk, and once none is left nothing stale survives to be followed — no
 generation tag on any wire, nothing on the delivery path. soren-ds needs no new
  machinery; 207 already files old destination arrays in a scrapyard and already
  has the per-core odd/even sweep. It made three issues **shorter**: replacing a
   box removes the old station instead of abandoning it, closing an app gets its
 places back instead of accumulating one dead station per station per app over a
    day, and the code-reclaiming sweep reaches a third kind of garbage — a box
                                                   whose every station has gone.

  **Two things soren-ds's docs never mentioned at all**, both now in the runtime
  doc: how a program is written back out as a map file plus a directory of the C
  of every box it places (so what's on the card *is* the program, rebuildable by
       the phase-4 generator and compiler, with device-written boxes written out
  identically to image ones), and what `serac` is — along with why this device
       isn't that shape, since it has no `main` to emit and no host toolchain to
                                                                         invoke.
