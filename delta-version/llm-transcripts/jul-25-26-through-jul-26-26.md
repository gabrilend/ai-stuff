## The shape of it


| Concern | Mechanism | Cost |

|---|---|---|

| Isolation | bubblewrap mount namespace; `--tmpfs` over the data disk, selective binds back | none at runtime |

| Sandbox repo | `git clone --shared` — borrows the object store via `alternates` | 108 KB, 8 ms |

| Working tree | sparse checkout, one project | 13 MB vs 4.8 GB |

| Ignored paths | read-only bind mounts, derived from `git check-ignore` | not copied |

| Durability | host-side watcher fetches from the sandbox every 5 s | commit → disk in ~1 s |


`★ Insight
─────────────────────────────────────`

**The durability guarantee comes from ordering, not from checking harder.** The
carry-back fetches into a staging ref *before* it consults the working tree at
all. So the commit is on disk before anything can object to it. A dirty tree, a
divergent history, a conflicting untracked file — each blocks the *visible*
update while the work is already safe. That's why every refusal message says the
commits are safe: a warning that reads like a failure sends someone hunting for
work that was never at risk.


This is a general move worth stealing. When a pipeline has one step that must
never fail and several that legitimately might, put the unconditional step first
and let the conditional ones fail loudly afterward. Reordering bought a
guarantee that no amount of error handling in the other order would have.

`─────────────────────────────────────────────────`


## Bugs this round caught


Four, all found by testing rather than reading. The **borrowed object store
resolved to itself** — the sandbox mounts at the monorepo path, so
`<monorepo>/.git/objects` inside pointed at the sandbox's own store, making the
borrowing silently circular; fixed with a dual-valid path bound read-only.
**Untracked files blocked every first carry**, because git won't fast-forward
over a file it can't vouch for — fixed by giving the real directory exactly
one writer. **Empty skeleton directories** read as unsaved work, since git
doesn't track empty directories so they never travel to disk. And the
**uncarried-commits check read a stale ref**, reporting work as uncarried
moments after carrying it.
