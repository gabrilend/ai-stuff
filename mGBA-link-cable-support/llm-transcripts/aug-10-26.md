**`update`** (50 lines) — clones `github.com/mgba-emu/mgba` into `source/` the
first time, and on every run after that hard-resets and fast-forwards instead.
The reset before the pull is deliberate: `install` normally hands the tree back
pristine, but a build killed by the out-of-memory reaper or a power cut leaves
our edits stamped in, and pulling onto those would fold our changes into
upstream's own history where nobody could tell them apart again.

**`install`** — resets the tree to upstream's commit, applies the patches,
compiles out-of-tree, installs into `files/`, then peels the patches back off.
The revert is wired to the script *exiting*, not to reaching the end, so a
compile that dies halfway still leaves clean source. That's what makes it
idempotent: the reset and the trap together mean every run starts from the same
tree regardless of how the last one ended.

**`run`** — starts whichever frontend the compile produced (`mgba-qt`,
`mgba-sdl`, `mgba`, in that order) on the most recently modified file in
`roms/`. A first argument that names a real file is the game; anything else is a
switch and goes straight through to the emulator.

## Config: command line and files, no Qt needed

mGBA picks its settings directory by calling `getcwd()` and looking for
`portable.ini` there. If it finds one, `[portable] path=config` redirects
everything to a subdirectory relative to that file. So `install` writes
`portable.ini` in the project root, keeps the real settings in `config/`, and
links `config.ini` back into the root where you'll actually see it. `run` `cd`s
to the project root as its last act before `exec` — that's load-bearing, not
tidiness, and the game path is resolved to an absolute path first so the move
can't change its meaning.

I didn't want to assert that from reading the source, so I tested it: adding
`logToStdout=0` to `config/config.ini` silenced the emulator's logger **only**
for the run started from the project root. The run started from elsewhere
printed its two lines unchanged, and nothing was written to a fake `HOME`. Your
`~/.config/mgba` stays untouched, so a half-finished link cable build can't
corrupt a working emulator's settings.
