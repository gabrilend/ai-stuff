# Issue 102: Player Progression Flow

## Phase
1 - Foundation Documents

## Current Behavior
The core mechanics document describes the timeline system, but doesn't document how the player's experience evolves across runs. The emotional and mechanical progression is implicit, not explicit.

## Intended Behavior
A document (docs/04-player-progression.md) should exist describing:
- The player's learning curve
- Key "aha" moments in the design
- How information is revealed through death
- The emotional arc from confusion to mastery
- The shift in player goals (survive -> save others -> perfect run)

## Progression Beats to Document
0. Boot camp flashback (the marked list - player learns they were always meant to die)
1. First run (confusion, death)
2. First recording (understanding death has information + clipboard flash)
3. First save (preventing a past death + red marker fading from a name)
4. First squad (multiple faded soldiers active)
5. First Festus attempt (scale of the challenge)
6. Pyrrhic victory (completing with casualties - some names stay marked)
7. True victory pursuit (the obsession with unmarking every name)

## Suggested Implementation Steps
1. Create docs/04-player-progression.md
2. Document each beat with mechanical and emotional notes
3. Include sample internal monologue or player thoughts
4. Map knowledge acquisition (what does the player learn and when)
5. Update docs/table-of-contents.md

## Notes
This document answers: "What does it feel like to play this game?"

The progression should show how the player's relationship with death changes - from failure to be avoided, to information to be gathered, to past selves to be saved.
