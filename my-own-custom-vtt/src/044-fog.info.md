# 044-fog

What somebody has ever seen. One bit per cell, set the first time that cell is
seen and never cleared.

Sight is recomputed from scratch and never stored. Memory accumulates forever and
is never recomputed. A corridor you walked an hour ago is in this and not in
sight — which is why the outbound filter sends **walls** for everything in
memory and **bodies** only for what is in sight. You keep the shape of a room you
have left and have no idea whether anybody is still standing in it.

Like sight, this is part of the security boundary rather than a drawing feature.

| Function | In | Out |
| --- | --- | --- |
| `fog_init` | fog, world, cell size (0 = one metre) | 1 / 0 |
| `fog_release` | fog | — |
| `fog_fold` | fog, world, body | — (sets bits, never clears) |
| `fog_remembers` | fog, x, y | 1 / 0 |
| `fog_cells_seen` / `fog_cell_count` | fog | count |
| `fog_copy` | destination, source | 1 / 0 — what rollback uses |

## A grid, in a project that says the map is not a grid

The two answer different questions.

A **rules grid**, if a ruleset has one, decides *where things may stand*. That is
a constraint on the world and is deliberately kept out of it.

This grid decides *how finely we record having been somewhere*, and memory is
approximate by nature — nobody needs millimetre precision on "have I been down
this corridor". Quantising turns an unbounded polygon-union problem into setting
bits, and setting bits is free.

They need not be the same size and neither knows the other exists.

At one metre per cell, the fixture's fifty-by-twenty map is 1,144 cells — under
150 bytes per viewer.

## The centre stands for the cell

The document says a cell is remembered when *any* part of it falls inside the
visibility polygon. Testing the centre is stricter: a cell whose corner was
glimpsed but whose middle was not stays unremembered.

That is the safer direction to be wrong in. Under-claiming means a map shows
slightly less than somebody saw; over-claiming means it shows a square metre of
floor they never really looked at — which is what open question 2.1 is about.

## One primitive, two callers

Folding asks `sight_point_visible`, the same function the outbound filter uses. A
second rasteriser written specially for the fog could disagree with the one that
decides what goes on a socket, and then a hole in the map and a leak would look
identical. A test asserts no remembered cell is one sight would have refused.

## Rollback restores it

`fog_copy` is what a turn being taken back uses. Fog goes back **with** the world
— a full state restore.

The cost is not pretended away: the person still remembers the corridor. They
looked at it. Their map closes over a room they can describe out loud, and the
screen ends up knowing less than they do.

It is still the right trade, because a fog left un-rolled holds a place reached
in a turn that never happened and contradicts the world every time anybody walks
there again — a permanent inconsistency, spreading, bought with one moment of
honesty about one person's memory.

**You cannot restore ignorance.** The program's job is to put the board back.
