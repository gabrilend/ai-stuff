# Issue 8-050a: Compute Semantic Color for Each Word-Cloud Word

## Priority
High (blocks 8-050b, 8-050c, 8-050e)

## Current Behavior

Each poem has a precomputed semantic color stored in `poem_colors.json`, assigned by `src/semantic-color-calculator.lua`. This calculator:

1. Loads color embeddings from `color_embeddings.json` (one embedding per color name: red, blue, green, purple, orange, yellow, gray)
2. Compares each poem's embedding to all color embeddings via cosine similarity
3. Assigns the color with the highest similarity score

However, **word-cloud words have no semantic color assignment**. The word page generator (`src/generate-word-pages.lua`) currently uses each poem's individual color, not a per-word color. There is no `word_colors.json` or equivalent mapping.

## Intended Behavior

During the embedding stage (Stage 6), after generating word embeddings, compute and cache the semantic color for each word-cloud word:

1. Load the existing `color_embeddings.json` (already generated by `semantic-color-calculator.lua`)
2. For each word in the word cloud, compare its embedding to all color embeddings
3. Assign the nearest color (highest cosine similarity)
4. Cache the results to `assets/embeddings/embeddinggemma_latest/word_colors.json`

### Output Format

```json
{
    "word_colors": [
        {"word": "silence", "color": "blue", "similarity": 0.782},
        {"word": "fire", "color": "red", "similarity": 0.891},
        {"word": "forest", "color": "green", "similarity": 0.834}
    ],
    "model": "embeddinggemma:latest",
    "generated": "2026-01-26 14:30:00",
    "count": 200
}
```

## Suggested Implementation Steps

### 1. Add color computation to `generate-word-pages.lua`

In the `generate_word_embeddings()` function (or as a new function called after it), after word embeddings are cached:

```lua
-- After saving word embeddings, compute word colors
local color_embeddings = load_color_embeddings()
local word_colors = {}
for word, word_embedding in pairs(word_embeddings) do
    local best_color, best_sim = compute_nearest_color(word_embedding, color_embeddings)
    table.insert(word_colors, {
        word = word,
        color = best_color,
        similarity = best_sim
    })
end
save_word_colors(word_colors)
```

### 2. Load color embeddings

The color embeddings file already exists at:
`assets/embeddings/embeddinggemma_latest/color_embeddings.json`

Generated by `src/semantic-color-calculator.lua` during Stage 6.5. Reuse the same data — no additional Ollama calls needed.

### 3. Reuse cosine similarity function

The `cosine_similarity()` function already exists in `generate-word-pages.lua:115-138`. Use it directly for word-to-color comparison.

### 4. Cache to word_colors.json

Save alongside existing embedding artifacts:
`assets/embeddings/embeddinggemma_latest/word_colors.json`

### 5. Make word colors available during HTML generation

In `generate_word_html()`, load `word_colors.json` and pass the per-word color to each page generator call, so downstream sub-issues (8-050b, 8-050c, 8-050e) can access it.

## Validation

- Every word with an embedding should have a color assignment
- Colors should be drawn only from the 7 defined semantic colors (red, blue, green, purple, orange, yellow, gray)
- The similarity scores should be in a reasonable range (typically 0.6-0.9 for related concepts)
- Spot-check: "fire" → red, "ocean" → blue, "forest" → green (sanity check)
