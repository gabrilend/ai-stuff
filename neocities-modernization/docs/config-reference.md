# Config Reference

What every section of `config.lua` is for, what it holds now, and how to do
the common changes by hand.

## Overview

All configuration lives in `config.lua` at the project root. It uses Lua table
syntax and is loaded via `libs/config-loader.lua`:

```lua
local config_loader = require("config-loader")
config_loader.set_project_root(DIR)
local config = config_loader.load()
```

Sections use vimfolds (`-- {{{ section_name` / `-- }}}`) for easy navigation in
editors.

**What is not in this file.** The values that change from one build to the next
are given on the `run.sh` command line (or in its menu, `run.sh -I`), not here:
`--threads`, `--pages`, `--poems-per-page`, `--chrono-per-page`,
`--wordcloud-words`, `--wordcloud-poems`, `--seed`, `--model`, `--server` and
`--boosts yes|no`. `run.sh` refuses to start without the ones the selected
stages need, lists every missing one at once, and records them all in
`output/generation-metadata.json` (Issue 10-065).

**Keeping this page true.** The section reference below is generated from the
comments in `config.lua`. After changing those comments or adding a section,
run `scripts/generate-config-reference`; `scripts/generate-config-reference
--check` says whether this page is out of date. To list settings that no
program reads, run `scripts/audit-config-keys`.

### color_associations

Each color's "essence" as a list of associated words -- concrete things AND abstract feelings/concepts. semantic-color-calculator embeds every word, mean-combines them into one per-color centroid (the same recombination used for long-poem chunks, Issue 10-050), and assigns each poem the color whose centroid it sits most ABOVE-baseline for (z-scored, hubness-corrected).

Why a list of associations instead of the bare color word: the bare word "red" embeds to a generic point that, by raw nearness, swallowed ~38% of all poems. A list (fire, blood, passion, rage...) pulls the anchor into the color's real semantic territory -- a poem about war or embers reads red even if it never says "red". Keep each list COHERENT (every word genuinely of that color); a coherent set averages to a clean anchor, an incoherent one to mush. These are a starting point -- edit freely; re-run stage 6.5 after.

### inference_servers

Issue 10-049: Inference-server configuration for embedding generation. Originally written for Ollama under 10-017; renamed and re-shaped for llama.cpp. Define multiple servers (local, remote GPU, etc.) and switch between them via TUI selection or CLI flags. Read by: libs/inference-server-config.lua CLI overrides: --server NAME, --model NAME, --list-servers

Fields per server:
      name: Label shown in the TUI and used with the --server flag
      description: Human-readable description
      host: Server hostname or IP
      port: Inference server's HTTP port
      available_models: the models this server can serve. There is no
                        default: every run names its model with --model
                        (owner, 2026-10-21: "we should not have a default
                        model. It should be manually specified"). Each entry:
        model: Identifier sent in the OpenAI request body (llama-server
               serves whatever it has loaded). Convention is the GGUF
               basename without ".gguf". Also the name of the model's cache
               folder under assets/embeddings/.
        model_path: (local models) the GGUF file, relative to the project
                    DIR; start-llamacpp-server.sh passes it to llama-server -m.
        embedding_prompt_prefix: (optional) prepended to every input
                                 (e.g. "clustering: " for nomic-embed-text v1.5).
        A model this server does not list is refused when its prefix or
        file is needed, rather than embedded without its prefix.
      launch_flags: (optional) Extra llama-server flags for THIS machine's
                    GPU, as a list of separate words ({ "--flash-attn", "off" }).
                    start-llamacpp-server.sh appends them after its own
                    flags. Only used by servers this project launches itself.
                    Put a GPU's limits here so they are stated choices, not
                    something llama.cpp quietly decides at load time.

## Common Customization Tasks

### Adding a New Poem Source

1. Add an entry to `sources`:
```lua
my_source = {
    enabled = true,
    format = "plaintext",  -- or appropriate format
    directories = {
        { name = "primary", path = "input/my-source" }
    }
}
```

2. Create an extractor script if the format needs custom parsing.

To switch a source off later, set `enabled = false` on its entry.

### Adding an External Sync

Add an `external` field to a directory entry:
```lua
{
    name = "my-dir",
    path = "input/my-source",
    external = {
        source = "/home/user/original-location"
    }
}
```

### Excluding a Poem

Add its ID to the right category in `excluded_poems`:
```lua
excluded_poems = {
    fediverse = { "113847291038475" },
    notes = { "embarrassing-draft" }
}
```

### Changing the Embedding Server

Pass `--server NAME` to `run.sh` (the stages that embed require it). `NAME`
must match the `name` of an entry in `inference_servers`; add an entry there to
make a new server available. The menu (`run.sh -I`) offers the entries as a
list.
