# generate-config-reference

Writes the "Section Reference" part of `docs/config-reference.md` from
`config.lua`'s own comments and current values.

## Why it exists

The reference used to be written by hand (Issue 10-019, April 2026) and was
never updated. By October it described a section that no longer existed, used
an old name for another, listed settings nothing read, and was missing seven
sections. `config.lua` already explains every section in the comment above it,
so the reference is now built from those comments and cannot fall behind.

## Usage

    scripts/generate-config-reference [--dir PATH]           rewrite the doc's generated region
    scripts/generate-config-reference [--dir PATH] --check   exit 1 if the doc is out of date; write nothing

Exit status: 0 written or up to date, 1 `--check` found it out of date,
2 `config.lua` could not be loaded or the doc lacks its markers.

## What it writes

Only the text between these two lines in the doc is replaced:

    <!-- BEGIN section reference: generated by scripts/generate-config-reference; edit config.lua's comments, not this -->
    <!-- END section reference -->

Everything outside them (the overview, the how-to guide, the removed-settings
table) is written by hand and left alone. A doc without both markers is refused
rather than overwritten.

For each top-level section of `config.lua`, in the file's order:

| Part | Comes from |
|---|---|
| heading | the section's name |
| description | the comment lines directly above the section (fold markers skipped) |
| table row per setting | the setting's name; its current value (a string, number or true/false as written; a nested table as "table of N", a list as "list of N"); the comment beside it, or else the comment lines directly above it |

A section whose value is a list or a single value gets one "Current value" line
instead of a table.

## To change what the doc says

Edit the comment in `config.lua`, then run the generator. Editing the
generated region of the doc directly is undone by the next run.

## Test

`scripts/generate-config-reference.test.sh` runs the generator on a throwaway
project and checks that the hand-written text survives, each comment lands in
the right place, `--check` reports staleness without writing, and a doc
without markers is refused untouched.
